# Changelog

## Unreleased
- Assembler: **Material** is back in the right-click **New** menu, just after Mesh
- Assembler: **Mesh** items now also save locked (user) normals and vertex colors (every color set, with its RGB / RGBA / A type, and which set is current), and Run puts them back on the new meshes. Mesh files published before this still run as before, without them
- Assembler: **folders have versions**. Right-click **Publish** on a folder records the version every item inside it is at, subfolders included, as the folder's next version. It can't be published while an item in it has changes not published yet; the message names them so you can publish them first. Like a file, the folder's Version column shows its version, and a `*` (e.g. `v002*`) once it no longer matches: an item added, deleted or renamed, or one published or switched to another version. Picking a version under **Versions** sets every item in the folder back to the version it recorded, and asks first only if that would lose an item's unpublished changes. Items deleted since are named as not restored; items added since are left as they are. Folder versions are kept in the hidden `.versions` folder next to it, follow it when it's renamed or moved, and are deleted with it
- Assembler: **build plans**. Right-click a folder (or empty space, for the whole tree) ▸ **Build Plan ▸ Export...** saves everything in it as one JSON file: its folders and items in build order, which are disabled, each Script's code, each Scene's Maya file path, and each Rig Module's module and parameters. Mesh, Joints, SkinCluster and the other published-data items are saved as empty entries to publish into, and versions and run logs aren't included. **Build Plan ▸ Import...** creates a plan's items in the folder, after what's already there; imported items start with no versions. Import checks the whole plan first (names, item types, rig modules and their parameter values, names already in the folder) and, if anything is wrong, lists every problem and creates nothing. Use it to share build templates, or to bring in a build an AI wrote
- **ControlShape Tool**: a library of control shapes with previews: 16 built-in presets (circle, square, triangle, half circle, star, cross, arrow, double arrow, four arrows, cube, sphere, cylinder, diamond, pyramid, pin, locator) plus your own: **Save Selected...** saves the selected control's shapes (without colors) as a preset in your Maya user folder (`kaiju_suite/control_shapes`), and **Delete** removes a saved one. **Create** (or double-click) makes a `<name>_ctrl` with the preset at each selected node's position and orientation, or one at the origin, at the chosen **Size**. **Replace** swaps the selected controls' shapes for the preset, keeping their color and line width, and their size with **Keep size**; a joint or group with no shapes gets its first one. **Edit Shapes** rotates (X / Y / Z by an angle), scales (**Bigger** / **Smaller**) and moves (+X ... -Z by a step) the selected controls' shapes around their pivots without moving the controls. **Mirror to Opposite** gives each selected control's opposite (`L_` / `R_`, ...) its shapes mirrored across X, keeping the opposite's color; **Copy from First** gives the other selected controls the first one's shapes. Color swatches set the shapes' index color (or turn it off), and **Set Line Width** their line width. Each is one undo step
- **DeltaMush Tool**: paint where a deltaMush acts. **Add DeltaMush** adds one on top of the selected meshes' deformers with every weight at 0, so it does nothing until you paint it in (or at 1, to paint it out). **Load Selected** picks the selected mesh and its deltaMush; **Paint** opens Maya's Paint Attributes tool on its weights. **Set Selected** sets the selected vertices (or faces, edges) to a value, **Flood** sets every vertex, **Invert** turns each weight w into 1 - w, **Mirror +X to -X** / **-X to +X** copies one half's weights onto the other, and **Select Affected** selects the vertices it acts on. Each is one undo step
- **SkinCluster Tool**: **Copy Skin** copies the first selected mesh's weights onto the other selected meshes, matching vertices by **Closest Point**, **UV** (current UV sets, wherever the meshes are) or **Topology** (same vertex IDs; needs the same vertex count). A target with no skinCluster is bound to the source's influences; a skinned one gets the influences it's missing. **Mirror Skin** mirrors the selected meshes' weights across X, +X to -X or back, matching joints by position. **Prune Weights** zeroes weights below a threshold, **Remove Unused Influences** removes influences with no weight, and **Select Influences** selects them. Each is one undo step
- **Pose Tool**: **Mirror** poses each selected control's opposite as its mirror image across X; **Flip** swaps the poses of the selected controls and their opposites, mirrored. Opposites are found by name (`L_`/`R_`, `_L`/`_R`, `l_`/`r_`, `left`/`right`, `Left`/`Right`, also camelCase like `leftEye`); a control with no side mirrors onto itself. Translate and rotate are worked out from each control's parent and joint orient, so world-aligned controls and joints mirrored with Behavior or Orientation all come out mirrored in the world (rotate axis isn't taken into account); scale and custom attributes are copied as they are. Locked or connected attributes on the other side are skipped with a warning. **Opposite** / **Add Opposite** select the other side; **Reset to Default** sets every keyable attribute to its default. Each is one undo step
- **Mesh Tool**: checks meshes for problems: n-gons, non-manifold geometry, lamina faces, zero-area faces, zero-length edges, open borders, faces without UVs, locked normals, vertices with no mirror across X, unfrozen transforms, construction history (deformers don't count), duplicate names and shapes not named `<mesh>Shape`. **Check** runs the turned-on checks (remembered) on the selected meshes, or every mesh if nothing is selected, and lists what each found per mesh; **Select** (or double-click) selects the faces, edges, vertices or meshes found. **Fix** repairs unfrozen transforms (like Freeze Transformations), history (keeps deformers), locked normals and shape names, as one undo step, then checks again
- Menu: the **Rig Module Editor** is no longer under **Kaiju ▸ Utilities**. Open it by double-clicking a Rig Module item in the Assembler
- Rig modules: **Simple IK** has a new **Color** parameter, a Maya index color (0 to 31, as in Drawing Overrides) that both its controls get; new items default to 17 (yellow), and 0 leaves Maya's default color. Existing Simple IK items get 17 too. The Rig Module Editor shows it as a drop-down of color swatches
- Rig modules: six new modules, each under **New** in the Assembler and edited in the Rig Module Editor like Simple IK. Every one has a **Color** parameter for its controls (default 17, yellow), checks its parameters before building and changes nothing if any are wrong, doesn't move your joints when it builds (except Spline IK with a curve, below), and is reverted by one undo:
  - **Root**: needs no joints. Builds `<name>_root_grp` at the world origin with a large flat root control and a smaller offset control under it; build the rest of the rig under the offset control. The root control's keyable **globalScale** (default 1) scales it evenly; its own scale channels are locked and hidden. Name defaults to `main`, control size to 10
  - **Single FK**: one joint. Builds `<name>_fk_grp` with a circle control on the joint, matching its orientation; the joint follows the control's translation and rotation
  - **FK Chain**: a start and end joint (at least 2 joints). Builds `<name>_fkChain_grp` with one circle control per joint, `<name>_01_fk_ctrl`, `<name>_02_fk_ctrl`, ..., each nested under the one before, so rotating a control carries everything below it. Turn off **End control** when the end joint is just a tip
  - **Stretchy IK**: like Simple IK (a rotate-plane IK control at the end joint and a pole vector control), in `<name>_stretchIk_grp`, and when the IK control is pulled further than the chain reaches, every bone lengthens by the same amount so the end joint stays on the control. Within reach bones keep their length. The IK control's **stretch** attribute (0 to 1, default 1) turns stretching off or blends it. Joints below the start joint can't have locked or connected translation. Its control names are the same as Simple IK's, so don't give a Simple IK and a Stretchy IK the same name. Deleting the group by hand leaves the stretch nodes driving the joints: undo the build instead
  - **IK/FK**: a start and end joint (at least 3, with a bend). Copies the joints into an IK chain and an FK chain inside `<name>_ikfk_grp`. The IK side works like Simple IK; the FK side has one nested circle control per joint. A switch control beside the end joint has an **ikFk** attribute: 0 is FK (the default), 1 is IK, values between blend. Your joints aren't reparented; they follow the blend. IK controls show only while ikFk is above 0, FK controls only while it's below 1
  - **Spline IK**: a start and end joint (at least 3) and an optional NURBS **Curve**. Builds `<name>_splineIk_grp` with a spline IK and two controls, a hip control at the start joint and a chest control at the end joint: moving them bends the spine, rotating them twists it, blending from hips to chest. With no curve it makes one through the joints; with a curve it works on a copy, leaving yours alone, and the joints snap onto it
- Assembler: new **Rig Module** item type (`.rig`), starting with **Simple IK**. The item holds only parameters; the rigging algorithm lives separately, in `rig/modules/`. The Type column shows the module, e.g. `Simple IK`, rather than "Rig Module". **New ▸ Simple IK** creates an item with default parameters. Double-clicking it opens the new **Rig Module Editor** on that item: change the name, start and end joints (**<<** picks the selected node), pole distance, control size and parent group, then **Save**. The editor lists anything that would stop a build in the current scene (missing or ambiguous joints, an end joint not below the start, fewer than 3 joints, a straight chain, a name already used, ...); **Check** re-checks after the scene changes. It asks before dropping unsaved edits, and reloads when the file changes on disk, e.g. when a version is restored. **Run** checks the parameters first and changes nothing if any are wrong, then builds `<name>_ik_grp` (under the parent, if set) holding a rotate-plane IK control at the end joint (the IK handle under it, the end joint's rotation following it) and a pole vector control on the chain's plane, `pole distance` out from the middle joint. Building doesn't move the joints. One undo reverts a Run. **Publish** saves the parameters as the next version. Right-click **Info** lists the parameters
- Assembler: right-click **Info** is now the last entry in the menu, below Rename and Delete, for every item type that has it
- Assembler: a **Scene** item now points to a Maya file instead of holding one. It's a `.scene` file that stores the file's path, and it's back in the **New** menu, just above Folder (**New ▸ Scene** asks for a name and creates an empty entry, which a build skips). **Run** imports the Maya file it points to; if that file no longer exists, the build stops there and names the missing path. Right-click **Publish** opens a file browser, starting in the current file's folder, and the `.ma` or `.mb` you pick becomes the next version, so **Versions** can point it back to an earlier file. Publish no longer needs a selection or exports anything, and cancelling the browser changes nothing. Double-clicking a scene, or right-click **Info**, shows the path and whether the file is missing; there's no Scene Tool. `.ma` and `.mb` files in an Assembler folder are no longer items: they don't show in the tree or run in a build, so replace them with Scene items that point to them
- Assembler: the right-click **New** menu is regrouped, with dividers: Script / Scene, Folder, Separator / Mesh, Joints, ControlShape / SkinCluster, DeltaMush, BlendShapes / Pose, Animation. **Material** is no longer in it
- Assembler: new **Separator** item type (`.sep`), for dividing the tree into sections. **New ▸ Separator** asks for a name and creates an empty file. Its Version and Type columns show `=====`. Separators have no Publish or Versions, are skipped by Run All and can't be disabled. Like any item, they can be dragged, renamed, copied and deleted
- New utility tools, one per Assembler item type except Script, Folder and Scene: **Joint Tool**, **Mesh Tool**, **SkinCluster Tool**, **DeltaMush Tool**, **BlendShape Tool**, **Material Tool**, **Pose Tool**, **Animation Tool** and **ControlShape Tool**. They're under **Kaiju ▸ Utilities**, and double-clicking an item of that type in the Assembler opens its tool. The windows are empty for now
- Assembler: the info window that double-click used to open (e.g. how many meshes a file holds) is now right-click **Info**. Scenes, whose window was empty, have no Info entry
- Menu: **Assembler** and **Renamer** are now directly in the **Kaiju** menu instead of under **Kaiju ▸ Utilities**
- Assembler: the step that's running now shows in light blue instead of yellow
- Assembler: the **Type** column only shows the file extension for Scene and Script items, which can be either of two kinds (e.g. `Scene(.mb)`, `Script(.py)`). Other types show just their name, e.g. `Mesh` instead of `Mesh(.mesh)`
- Assembler: a new **Warning** run status, in yellow. A step that runs but logs a warning (a skipped missing node, a `cmds.warning` in a script, ...) turns yellow instead of green, and the build goes on. After a run with warnings, a Maya warning names the steps that had them. Hovering an yellow or red step says to check its log
- Assembler: every step now saves a log of its last run, and right-click **Show Log** opens it in a window, warnings in yellow and errors in red. The log has when it ran, how long it took and its status, then what the step did (e.g. which meshes were bound), Maya's output while it ran (`print`, `cmds.warning`, MEL `print` and `warning`, errors) and, if it failed, the full error with its traceback. Logs are kept in a hidden `.logs` folder next to the items, follow an item when it's renamed or moved, and are deleted with it. **Show Log** is greyed out for an item that hasn't run yet
- Assembler: **Pose**, **SkinCluster**, **Animation**, **DeltaMush**, **BlendShapes** and **ControlShape** no longer stop the build when a node is missing from the scene. They skip it, apply everything else, and log a warning naming what was skipped (e.g. `Skipped missing meshes: head`), so the step ends yellow. SkinCluster skips a mesh whose influences aren't all in the scene (`Skipped leg: missing influences knee, ankle`) rather than binding it to only some of them; Animation skips curves whose node or attribute is missing. Pose's skipped locked, connected or missing attributes are now logged as a warning too. A name that matches several nodes, or a mesh whose vertex count has changed, still stops the step before it changes anything
- Assembler: new **ControlShape** item type (`.ctrl`), for swapping in the curve shapes of controls. **New ▸ ControlShape** creates an empty entry, which a build skips. Right-click **Publish** saves every NURBS curve shape under each selected control (select the control or one of its shapes) as the next version: degree, form, knots and CVs, plus the shape's color overrides and line width. The CVs are saved relative to the control's pivot, in the control's own space, so the shape doesn't depend on where the control is. With nothing selected, or a selected node with no curve shapes, a dialog says so and names it. **Run** finds each control by name, deletes its current curve shapes (so a different number of CVs is fine) and creates the saved ones relative to the control's pivot as it is now: if the control or its pivot has moved since publishing, the shape moves with it. Other shapes under the control, such as locators, are left alone. If a control is missing or its name matches several nodes, Run changes nothing and says which. One undo reverts a Run. Double-clicking shows how many controls and curve shapes the file holds and the control names
- Assembler: double-clicking a folder opens it in Explorer (Finder on macOS). Double-click no longer expands or collapses folders; use the arrow next to them
- Assembler: new **Joints** item type (`.jnt`). **New ▸ Joints** creates an empty entry, which a build skips. Right-click **Publish** saves the selected joints and every joint below them (position, rotation, joint orient, rotate order, scale, segment scale compensate, radius, preferred angle and labels) as the next version; with no joints selected, a dialog says so. **Run** always creates new joints and never changes existing ones: a name that's already taken gets the next free one (`spine_jnt` becomes `spine_jnt1`), and each joint stays under its own new parent. A joint whose parent isn't in the file goes under the scene's node of that name, or the world if there's none. One undo reverts a Run. Double-clicking shows how many joints the file holds and its root joints
- Assembler: new **Mesh** item type (`.mesh`). **New ▸ Mesh** creates an empty entry, which a build skips. Right-click **Publish** saves the selected meshes (point positions, faces, UV sets, hard edges, position/rotation/scale and the parent's name) as the next version; selecting a mesh's shape counts as selecting the mesh. If nothing is selected, or something selected isn't a mesh, a dialog says so and names it. **Run** always creates new meshes, without construction history, and never changes existing ones: a name that's already taken gets the next free one (`body` becomes `body1`, with shape `body1Shape`). Each new mesh gets the default material (`initialShadingGroup`) and goes under the scene's node with its saved parent's name, or the world if there's none; if several nodes have that name, nothing is created and an error names them. One undo reverts a Run. Double-clicking shows how many meshes the file holds and their names
- Assembler: new **SkinCluster** item type (`.skin`). **New ▸ SkinCluster** creates an empty entry, which a build skips. Right-click **Publish** saves the skinCluster of each selected mesh (select the mesh or its shape) as the next version: its name, influences, weights, skinning method, normalize mode, max influences, and the dual quaternion blend weights when the method is weight blended. If nothing is selected, no mesh is selected, or a mesh has no skinCluster, a dialog says so and names those meshes. **Run** finds the meshes and influences by name, replaces any skinCluster already on the mesh with a new one bound to exactly the saved influences under the saved name, and restores the weights and settings. It checks every mesh first and changes nothing if a mesh or influence is missing (one error lists them all, e.g. `Missing influences: knee, ankle`) or a mesh's vertex count differs from the file. Weights aren't remapped onto a changed mesh. One undo reverts a Run; redo after that brings back the skinCluster with Maya's default weights instead of the saved ones, so run the file again rather than redoing. Double-clicking shows the meshes, their skinClusters and influence and vertex counts
- Assembler: new **DeltaMush** item type (`.dmsh`). **New ▸ DeltaMush** creates an empty entry, which a build skips. Right-click **Publish** saves every deltaMush on the selected meshes (smoothing iterations and step, inward and outward constraint, distance weight, displacement, pin border vertices, envelope, and the painted weights) as the next version; if nothing is selected, or a selected mesh has no deltaMush, a dialog says so. **Run** finds the meshes by name and replaces a deltaMush of the same name, creating it after the mesh's other deformers so it sits on top of skin. If a mesh is missing, its vertex count has changed, or the name belongs to another node, Run stops with one error and changes nothing. One undo reverts a Run. Double-clicking shows how many deltaMush nodes the file holds and on which meshes
- Assembler: new **BlendShapes** item type (`.bshp`). **New ▸ BlendShapes** creates an empty entry, which a build skips. Right-click **Publish** saves every blendShape on the selected meshes as the next version: its envelope and base weights, and for each target its name, weight, per-vertex weights and the moved vertices of each in-between. A target still connected to a sculpt mesh is saved from that mesh, so the file doesn't need the target meshes. With no meshes selected, or a selected mesh without a blendShape, a dialog says so. **Run** checks first that each mesh exists and has the saved number of vertices, and changes nothing if not. It then replaces any blendShape with the same name with a new one at the front of the deformer chain, so it sits under a skin whatever order the steps run in. No target meshes are created. One undo reverts a Run. Double-clicking shows how many blendShapes and targets the file holds and their meshes
- Assembler: new **Material** item type (`.mat`), for shading networks with their textures. **New ▸ Material** creates an empty entry, which a build skips. Right-click **Publish** saves, from the selected meshes or faces, their shading groups and everything upstream of them (materials, file textures, place2d nodes, ...) plus which shading group is on which mesh or faces, as the next version. Meshes aren't saved, and neither is the default lambert1 network, though meshes left on it are recorded. Texture images aren't copied: the file keeps their paths. Publish stops with a dialog when nothing is selected or when no mesh or face is selected. When a texture file it would reference doesn't exist on disk, it lists them and asks whether to publish anyway. **Run** checks first that every mesh in the file exists; if any is missing, one error lists them and nothing changes. It then recreates the networks and re-applies the assignments, per face where they were per face. A shading group, material or texture that already exists with the same name and type is used as it is instead of being duplicated, so running twice changes nothing. One undo reverts a Run. Double-clicking shows the file's shading groups, meshes and number of textures
- Assembler: new **Pose** item type (`.pose`), values only, no keys. **New ▸ Pose** creates an empty entry, which a build skips. Right-click **Publish** saves, for each selected node (controls, joints, any node), the value at the current frame of every keyable, unlocked attribute, including your own (numbers, on/off and enum attributes), even if it is animated or connected; with nothing selected, or nothing keyable, a dialog says so. **Run** sets those values back on the nodes of the same names. It creates no keys and leaves existing keys alone (a keyed attribute just changes its current value). It checks first that every node is in the scene and, if not, names the missing ones and changes nothing. Attributes that are now missing, locked or driven by a connection are skipped, and the message lists them, e.g. `Skipped 2 attributes: ctrl.translateX (locked), ctrl.rotateY (connected)`. One undo reverts a Run. Double-clicking shows how many nodes and attributes the file holds
- Assembler: new **Animation** item type (`.anim`). **New ▸ Animation** creates an empty entry, which a build skips. Right-click **Publish** saves the keyframes on the selected nodes as the next version: for each animated attribute its keys (time, value, tangent types, angles and weights, breakdowns, tangent and weight locks), weighted tangents, and pre/post infinity. Driven keys aren't saved. With nothing selected, or nothing selected that has keys, a dialog says so. **Run** puts the keys back on the same attributes, found by node name: each attribute in the file loses its current keys first, and attributes not in the file keep theirs. Keys go back on their saved frames (no offset), in the scene's current time unit. If a node or attribute is missing, Run changes nothing and names everything missing. One undo reverts a Run. Double-clicking shows how many attributes, nodes and keys the file holds and its frame range. These files are JSON, so Maya's own animImportExport `.anim` plug-in can't read them
- Assembler: right-click **Publish** on a scene now exports the current selection into the scene as its next version, in one click: it doesn't ask first, since the content it replaces stays in Versions. When it's done it shows e.g. `Published Scene ball.ma v003`, as scripts do. Publish checks first that something is selected; if not, a dialog says so and nothing is exported, instead of an error in the Script Editor. Double-clicking a scene still opens its window, but the window is empty for now: the **Export Selected** button is gone, since Publish does that
- Assembler: a script open in the Script Editor now reloads when its file changes on disk, e.g. after switching versions. If you've typed in that tab since loading it, you're asked first. Maya's own reload prompt failed with `confirmDialog: Object 'scriptEditorPanel1Window' not found` and left the old text in the tab. Applies to tabs the Assembler opens, and to any open tab for a script whose version you switch
- Assembler: scenes and scripts keep a version history. Right-click **Publish** saves the item as it is now as its next version (v001, v002, ...), unless that content is already published. The **Versions** submenu lists the five newest versions with their date and size, with a check next to the current one; picking one switches to it straight away. With more than five, **Show More...** opens a window with every version and a **Restore** button for each. Switching only asks first if the item has unpublished changes, since those would be lost. Every Export Selected publishes a scene's next version, and the scene's window shows the current version. The tree now has **Name**, **Version** and **Type** column headers; drag the edges to resize Name and Version (the widths are remembered), and Type fills the rest. The Version column shows the version each item is at, in orange when it isn't the latest, with a `*` (e.g. `v002*`) when it has changes not published yet. It updates as soon as the file is saved, without a refresh. Versions are kept in a hidden `.versions` folder next to the item, never show in the tree, and follow the item when it's renamed or moved. Deleting an item deletes its versions; a pasted copy of an item starts with none
- Assembler: right-click **Copy** and **Paste** (or Ctrl+C / Ctrl+V in the tree) duplicate items and folders on disk. Paste goes into the folder you right-click, or just below the item you right-click. A name that's already taken gets `_copy` added (then `_copy2`, ...). Copies keep their disabled state, and a copied folder keeps its order and disabled items
- Assembler: while a run is going, each step's name turns yellow as it runs, then green if it succeeded or red if it failed. Colors clear when a new run starts or when you click the refresh button
- Assembler: right-click **Rename** renames an item or folder. Files keep their extension, and the item keeps its place in the order and its disabled state
- Assembler: **Remove** on the right-click menu is now **Delete**
- Assembler: the tree hides file extensions and shows each item's type and extension, e.g. `Script(.py)` or `Scene(.mb)`, in a column on the right; folders show none. The search box matches the name without its extension
- Assembler: names are no longer color-coded by type (scripts blue, MEL orange, scenes yellow). Disabled items are still greyed out
- Assembler: folders can be disabled and enabled from the right-click menu. **Run All** skips a disabled folder and everything in it, including nested folders. Disabled folders are crossed out and their contents greyed. **Run All in** a disabled folder itself still runs it, like running a disabled script directly
- Assembler: scripts, scenes and folders are now separate "products", one module each under `tools/assembler/products/`. New item types can be added by dropping in a module (see README)
- Assembler: **Run All** now runs a full build. Scenes are imported in their place in the tree, between scripts. A build that imports a scene can't be undone as one step, because Maya clears undo on import
- Assembler: scenes can be disabled and enabled like scripts, and can be included in **Run N Selected**
- Assembler: right-click **New ▸ Script / Folder / Scene** replaces Add Script…, Add Folder… and Export Selected…. **New ▸ Scene** creates an empty scene entry without needing a selection; a build skips empty scenes
- Assembler: double-clicking a scene opens a small window for it. The window shows whether the scene is empty, or its size and when it was saved, and has an **Export Selected** button that writes the current selection into that scene. It asks first if the scene already has content. The window stays open while you work, so you can change the selection and export again
- Assembler: double-clicking a scene no longer imports it (use **Run**), and **Open in Script Editor** / **Import Scene** are gone from the right-click menu. Double-clicking a script still opens it
- Assembler: disable or enable scripts from the right-click menu; disabled scripts are shown crossed out
- Assembler: select several scripts (Ctrl/Shift-click) and run them together in tree order, including disabled ones, as one undo step; stops at the first failing script
- Assembler: **Run All** on a folder (or on empty space for the whole snippets folder) runs every enabled script under it, top to bottom, as one undo step
- Assembler: drag items between others to reorder them; the order and disabled state are saved in a hidden `.assembler.json` in each folder, so they survive reopening and travel with the folder. New files appear at the bottom
- Assembler: the folder path field is gone; the folder button now opens the folder picker directly, starting in the current snippets folder (hover it to see the path)
