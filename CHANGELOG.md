# Changelog

## Unreleased
- Assembler: **Material** is back in the right-click **New** menu, just after Mesh
- Assembler: **Mesh** items now also save locked (user) normals and vertex colors (every color set, with its RGB / RGBA / A type, and which set is current), and Run puts them back on the new meshes. Mesh files published before this still run as before, without them
- Assembler: the right-click menu runs a folder with **Run '<folder>'** (no longer **Run All**), and the **Build Plan** submenu is now **Build**. There is no Run All on empty space, and no Rebuild, Run up to Here or Run from Here
- Assembler: **build report**. After **Run '<folder>'**, a Build Report window lists every step with its status (OK, Warning, Error, or Skipped for steps after a failure), how long it took, and a **Log** button (or double-click) that opens its log. Below are the counts per status and the total time; **Copy as Text** copies the report as plain text. Each Run All replaces the last report. Running selected items doesn't open one
- Assembler: **headless build**. `mayapy -m kaiju_suite.tools.assembler.headless <build_folder> [--new-scene] [--save out.ma]` builds a folder with no UI, like Run All, for batch rebuilds and automatic rig checks. It prints each step's status and messages and exits non-zero if a step failed (`--save` only saves a build with no failed step). From Python, `headless.build(folder)` returns each step's status and messages. See the README
- Assembler: **Scene items store portable paths**, so a build folder works on another machine or after it's moved. When you publish a Maya file inside the folder that holds the Scene item (or a subfolder of it), the item stores the path relative to that folder, e.g. `files/hero.ma`. A file under the folder in the `ASSET` environment variable is stored as `$ASSET/...`, so each machine can point `ASSET` to its own copy. Any other file is stored as an absolute path, as before. Scene items published before this hold absolute paths, which still work. Right-click **Info** shows both the stored text and the file it points to, and a build plan keeps the stored text
- Assembler: **SkinCluster, DeltaMush and BlendShapes survive topology changes**. Publish now also saves each mesh's rest point positions. When a mesh's vertex count has changed since, Run no longer stops: each vertex gets the skin weights, deltaMush weights, or blendShape deltas and weights of the saved vertex closest to it, and the step logs a warning naming the mesh and both vertex counts. Files published before this change have no positions and still need the same vertex count
- Assembler: **Update from Scene**. Right-click a published Joints, Mesh, SkinCluster, DeltaMush, BlendShapes, Material, Pose, Animation or ControlShape item ▸ **Update from Scene** publishes it again from the nodes already named in its file, as the next version, without selecting anything: for "same meshes, new weights". Material items keep the faces they were published with. If any of those nodes is missing from the scene, or several nodes have its name, nothing is published and the message names them. Content that hasn't changed adds no version. Empty items don't have the entry
- Assembler: **compare versions**. Right-click a Joints, Mesh, SkinCluster, DeltaMush, BlendShapes, Material, Pose, Animation or ControlShape item ▸ **Versions ▸ Compare With** lists its other versions; picking one opens a window saying what changed from that version to the current file. SkinCluster and DeltaMush name the meshes added and removed, the influences added and removed, and on how many vertices each mesh's weights changed and by how much at most, plus any changed settings. Joints and Mesh name the joints and meshes added, removed and changed (for meshes: points moved and the largest move, topology, UVs, hard edges, parent, transform). The other data items get a general summary of what was added, removed and changed in the file
- Assembler: new **Curves** item type (`.crv`), for NURBS curves that aren't controls (Spline IK curves, wire deformer curves, guides). **New ▸ Curves** sits after ControlShape. Right-click **Publish** saves the selected curves (select a curve or its shape): name, parent name, translate, rotate, scale and rotate order, and each curve shape's degree, form (open, closed, periodic), knots, CVs, color overrides and line width. Only selected curves are saved, not curves below them; a selected curve under another selected one stays under it. **Run** always creates new curves and never changes existing ones, as Mesh and Joints do: a name that's taken gets the next free one (`spine_crv` becomes `spine_crv1`, and the message lists them). A curve goes under the scene's node with its saved parent name, or under the world if there's none; if several nodes have that name, Run stops before creating anything. One undo reverts a Run. Right-click **Info** (or double-click) lists the curves. Rational curve weights aren't saved
- Assembler: new **Sets & Layers** item type (`.sets`), for object sets (animator control sets, export sets, sets inside sets) and display layers. **New ▸ Sets & Layers**, next to Pose and Animation, creates an empty entry, which a build skips. Right-click **Publish** saves the selected object sets, with every set nested in them, and the selected display layers as the next version: each set's members, and each layer's members, display type (normal, template, reference), visibility, hide on playback and color. Select the sets and layers themselves (e.g. in the Outliner), not their members; with nothing selected, or no set or layer selected, a dialog says so. Shading groups and deformer sets aren't saved. **Run** creates each set and layer, or reuses one of the same name that's already in the scene, adds the saved members found by name (other members stay) and sets each layer's display settings. Members missing from the scene are skipped with one warning (e.g. `Skipped missing members: arm_ctrl`), so the step turns yellow. A member name that matches several nodes, or a set or layer name already used by another kind of node, stops the step before it changes anything. One undo reverts a Run. Double-clicking, or right-click **Info**, shows the file's sets and layers; there's no Sets & Layers tool
- Assembler: new **Output** item type (`.out`), a build step that saves the built rig to a deliverable file, so **Run All** can end with a file to hand over. **New ▸ Output** (last in the menu, after Check) asks for a name and creates an empty entry, which a build skips with a warning. Right-click **Publish** opens a save-file browser; the path you pick, ending in `.ma`, `.mb` or `.fbx`, becomes the next version, so **Versions** can point it back. Like Scene, the path is stored relative to the Output's folder when the file is under it (or as `$ASSET/...`), so the build folder still works when moved or opened on another machine. **Run** exports the whole scene there in that format, creating the folder if needed; the open scene keeps its own name. FBX loads the fbxmaya plug-in when needed and stops with a clear error if it can't. Two optional clean-ups run first, as one undo step: **Delete Unused Nodes** (as Hypershade's) and **Hide Joints** (draw style None; joints with a locked or connected draw style are skipped with a warning). Double-click shows the path, format and clean-ups, with buttons to turn each clean-up on or off (each change is a new version). Build plans include an Output's path and clean-ups
- Assembler: new **Check** item type (`.chk`), a build step that looks for rig problems and changes nothing. **New ▸ Check** (in the last group of the menu, just before Output) creates one with every check turned on: **Naming** (transform and joint names, without namespace, that don't match a regular expression; by default parts of letters and digits joined by underscores, such as `L_arm_ctrl`, so Maya's `pCube1` or `joint1` are flagged), **Unfrozen transforms** (controls and meshes whose translate, rotate, scale or shear isn't at its default; groups and joints are left alone), **Construction history** (modeling history left on meshes and curves; deformers don't count) and **Unknown nodes**. **Run** logs what each check found as a warning, so the step ends yellow (Warning) and the build goes on; with nothing found it ends green. Double-click opens a window listing the checks, with buttons to turn each on or off and to set the naming pattern; the file keeps those settings, **Publish** saves them as the next version, and build plans carry them. The checks live in `core/checks.py`
- Assembler: new **Connections** item type (`.conn`), for utility node networks (multiplyDivide, plusMinusAverage, condition, blendColors, remapValue, multMatrix, ...) and direct connections between rig parts, without a Script. **New ▸ Connections** creates an empty entry, which a build skips. Right-click **Publish** saves, from the selected nodes, every connection between them plus the utility nodes in between: select the two ends (e.g. a control and a joint) and the network linking them comes along; select a utility node to save it even if it isn't between selected nodes. Each utility node is saved with its type and only the values that differ from the default, as readable JSON. Selected controls and joints aren't saved, only found by name on Run. Connections through a unit conversion are saved as direct ones; Maya adds the conversion again on Run. Publish stops with a dialog when nothing is selected, when there's nothing to save, or when a selected node is an anim curve, deformer, set or other node another item type covers. **Run** replaces a utility node of the same name and type (its other connections go with it), creates the rest and reconnects everything by name. A missing scene node, or a connection to an attribute it doesn't have, is skipped with a warning. A scene node whose name matches several nodes, or a utility node's name taken by another type, stops the step before it changes anything. One undo reverts a Run. Right-click **Info** shows the utility nodes, how many connections, and the scene nodes they link
- Assembler: new **Attributes** item type (`.attr`), for the "lock and hide" pass of a rig. **New ▸ Attributes** (after Pose and Animation) creates an empty entry, which a build skips. Right-click **Publish** saves, for each selected node, its custom attributes (type, min/max, default, enum names, keyable, shown in the channel box, locked) and the locked/keyable/channel box state of its translate, rotate, scale and visibility channels, as the next version. Number, angle, distance, integer, bool, enum and string attributes are saved; compound attributes (e.g. double3) and message attributes aren't. **Run** finds the nodes by name, adds the attributes a node is missing, updates the ones it has (their current values are left alone, and attributes not in the file are kept) and applies the lock/hide state. A missing node is skipped with a warning; a name that matches several nodes, or an attribute that exists with a different type, stops the step before it changes anything. One undo reverts a Run, except that a min or max the Run removed isn't brought back (a Maya limitation). Double-click or right-click **Info** shows how many nodes and custom attributes the file holds
- Assembler: new **Constraints** item type (`.cnst`), for parent, point, orient, scale, aim and pole vector constraints. **New ▸ Constraints** (next to Pose and Animation) creates an empty entry, which a build skips. Right-click **Publish** saves every such constraint driving the selected nodes, or the selected constraint nodes themselves, as the next version: its targets and their weights, offsets (per target for parent constraints), skipped axes, interp type, and for aim constraints the aim, up and world up vectors, world up type and world up object. With nothing selected, or a selected node with no constraint, a dialog says so and names it; two constraints with the same name can't be published together. **Run** finds the constrained nodes and targets by name and replaces a constraint of the same name. A constraint whose constrained node, target or world up object is missing is skipped with a warning naming them, and the rest are created. If a name matches several nodes, a constraint's name belongs to another node, or a constrained node already has a differently named constraint of the same type (Maya would merge them), Run stops with one error and changes nothing. One undo reverts a Run. Right-click **Info** shows how many constraints of each type the file holds and the constrained nodes. New, empty **Constraint Tool** under **Kaiju ▸ Utilities**, opened by double-clicking a Constraints item
- Assembler: new **Set Driven Keys** item type (`.sdk`), under **New**, after Animation. **Publish** saves the driven keys on the selected nodes (select the driven nodes, not the drivers): for each driven key curve its driver and driven attributes, keys, tangent types, angles and weights, locks and pre/post infinity. Attributes driven by several drivers are saved with each of them. Time-based keys are left to Animation. **Run** finds the nodes and attributes by name and, on each driven attribute in the file, replaces its driven keys with the saved ones, keeping the curves' names; several drivers on one attribute add up through a blendWeighted, as with Maya's Set Driven Key. Missing nodes and attributes are skipped with a warning. It changes nothing and names the problem if a name matches several nodes, or a driven attribute is locked or driven by something else (a constraint, keys, a connection). Driven keys on other attributes are left alone. One undo reverts a Run. Right-click **Info** counts the curves, attributes and keys and lists the drivers
- Assembler: new **Wrap** item type (`.wrap`), for clothes, eyebrows and props that ride on the body. **New ▸ Wrap** (next to BlendShapes) creates an empty entry, which a build skips. Right-click **Publish** saves every wrap and proximityWrap on the selected meshes as the next version: the meshes each deforms, its driver meshes, its settings (wrap: envelope, weight threshold, max distance, auto weight threshold, exclusive bind, falloff mode, and each driver's dropoff, smoothness and influence type; proximityWrap: envelope, wrap mode, max drivers, falloff and dropoff scale, scale compensation, coordinate frames, smooth normals, span samples, smooth influences, soft normalization, and each driver's strength, falloff start and end, dropoff rate and overrides) and a proximityWrap's painted weights. Only mesh drivers are supported, and falloff ramps aren't saved. If nothing is selected, or a selected mesh has no wrap, a dialog says so. **Run** finds the meshes and drivers by name, replaces a deformer of the same name and type, and binds a new one after the mesh's other deformers, so it sits on top of skin. A wrap gets a new hidden `<driver>Base` mesh, made from the driver as it is when Run binds it; a proximityWrap binds to the driver's undeformed shape. A missing mesh is skipped, and a deformer whose driver is missing is skipped, each with a warning. A name matching several nodes, a vertex count that changed on a mesh with painted proximityWrap weights, or a name taken by another node stops Run with one error before anything changes. A wrap with no painted weights binds to a mesh whose topology changed. One undo reverts a Run. A new empty **Wrap Tool** under **Kaiju ▸ Utilities** opens on double-click; right-click **Info** shows how many wraps and proximityWraps the file holds, their meshes and drivers
- Assembler: new **Deformers** item type (`.dfm`), in the **New** menu after BlendShapes. Select meshes and right-click **Publish** to save their cluster, softMod, wire, lattice and nonLinear (bend, twist, squash, flare, sine, wave) deformers, in the order they evaluate: each one's settings, the vertices it deforms on each mesh, its painted weights, and its handle (with its parent), lattice and base (divisions and points) or wire curves (dropoff and base wire shape). skinCluster, deltaMush and blendShape aren't included; they have their own items. **Run** finds the meshes by name and rebuilds each deformer by name on top of the meshes' existing deformers, replacing one of the same name; other deformers are left alone. Missing meshes are skipped with a warning, and so is a wire whose curve is missing; a handle whose parent is missing is left in the world with a warning. A mesh or curve name that matches several nodes, a changed vertex count, or a name taken by another node stops the Run before anything changes. One undo reverts a Run. Double-clicking an item opens the new, empty **Deformer Tool** (under **Kaiju ▸ Utilities**); right-click **Info** lists the deformers, meshes and wire curves
- Assembler: new **Pose Correctives** item type (`.psd`), under **New** with BlendShapes, Deformers and Wrap, for poseInterpolator nodes (Maya's Pose Editor). Select poseInterpolators, or the joints that drive them, and right-click **Publish**: it saves each one's driver nodes (with twist axis and Euler twist), its settings (regularization, output smoothing, interpolation, negative weights, rotation and translation), every pose (name, the driver rotations and translations it stores, Swing and Twist / Swing Only / Twist Only, falloffs, independent, enabled) and which attributes each pose drives, usually BlendShapes targets. **Run** loads the poseInterpolator plug-in if needed, then rebuilds each one by name, replacing one of the same name, and reconnects its outputs; put it after the BlendShapes item it drives. Interpolators whose driver is missing, and outputs whose blendShape or target is missing, are skipped with a warning. If a driver, an output node or an interpolator's name matches several nodes, or the name belongs to another kind of node, Run stops before changing anything. One undo reverts a Run. It has no utility tool yet: double-click shows what the file holds
- **Joint Tool**: **Orient** points each selected joint's **Aim** axis at its first child joint and its **Up** axis as close to the chosen **World Up** as it can (any of ±X/±Y/±Z), putting it all in the joint orient (rotate and rotate axis become 0). With **Children** it orients every joint below too; with **Zero end joints** end joints get a zero joint orient so they line up with their parent. **Zero End Orients** does just that for every end joint in or below the selection. Nothing moves in the world, and children that aren't joints stay where they were. **Mirror** copies the selected joints and the joints below them across X, **Behavior** or **Orientation**, naming the copies after the other side (`L_`/`R_`, `_l`/`_r`, `left`/`right`, ...); it changes nothing if one of those names is already used. **Insert** adds a number of evenly spaced joints between each selected joint and its child joint, named `<joint>_split_01`, ... **Toggle Local Axes** shows the selection's local axes, or hides them if they're all shown, and **Set Radius** sets the joints' radius; with **Hierarchy** both include everything below. The options are remembered. Each is one undo step
- **SkinCluster Tool**: new **Weights** and **Influences** sections. **Limit Influences** keeps only the largest **Max influences** weights (default 4, remembered) on each vertex of the selected meshes and scales them back up to sum to 1; **Normalize Weights** makes each vertex's weights sum to 1. **Weight Hammer** gives each selected vertex (or the vertices of selected edges, faces) the average weights of the vertices around it. **Copy Vertex Weights** remembers the one selected vertex's weights and **Paste Vertex Weights** gives them to the selected vertices; pasting onto a mesh whose skinCluster lacks one of the influences names them and changes nothing. **Add Joints** adds the selected joints to the selected mesh's skinCluster at zero weight; **Remove Joints** removes them, sharing their weight out over each vertex's other influences so weights stay normalized (a vertex weighted only to removed joints goes to the closest joint left). Each is one undo step
- **Animation Tool**: **Mirror** gives each selected control's opposite the mirror image of its animation across X, replacing the opposite's keys; **Flip** swaps the animation of the selected controls and their opposites, mirrored. Opposites are found by name as in the Pose Tool, a control with no side mirrors onto itself, and values are mirrored the same way the Pose Tool mirrors poses (from each control's parent and joint orient). Key times, tangent types and angles, weights and pre/post infinity are kept, with values flipped where the channel flips. Where the two sides' translate or rotate channels don't line up as a plain flip (e.g. joints mirrored with Orientation, or a different rotate order), that group is baked on every frame between its first and last key instead, with default tangents. **Frame offset** (remembered) moves the mirrored keys, e.g. by half a cycle for a walk. An attribute keyed only on the destination loses its keys and takes the source's mirrored value. Locked or connected attributes on the other side are skipped with a warning. Each is one undo step
- Rig modules: new **Space Switch** module, under **New** in the Assembler and edited in the Rig Module Editor. Pick a **Control**, a **Driven group** above it (e.g. its offset group; leave it blank to insert a new `<control>_space_grp` between the control and its parent), and the **Spaces** as `label=node`, separated by commas (e.g. `world=main_offset_ctrl, chest=chest_ctrl, head=head_ctrl`; a bare node name is its own label). Building adds a keyable **space** attribute to the control, one entry per space, and a parent constraint on the driven group with one target per space; the attribute switches which one the control follows. **Default space** sets where it starts (blank is the first). Building doesn't move the control. It checks first (missing or ambiguous nodes, a driven group that isn't above the control or whose translate/rotate is locked or connected, a space node that moves with the control, labels used twice, a control that already has spaces) and changes nothing if anything is wrong. One undo reverts it
- **BlendShape Tool**: sculpt corrective shapes on skinned meshes. Pose the rig, select the skinned mesh and click **Start Sculpt**: it makes `<mesh>_sculpt`, a copy of the posed mesh, and hides the original. Sculpt the fix on the copy, then (in the same pose) **Create Corrective** works out the shape that, applied before the skin, makes the posed mesh match the sculpt, and adds it as a target (named in the box, or `corrective`, `corrective1`, ...) on a blendShape at the front of the deformer chain, made as `<mesh>_correctives` if the mesh has none there yet. No plugin is needed. It's exact for a skinCluster (linear skinning); with a deltaMush or other smoothing deformer after the skin it only gets close. The sculpt is deleted, or hidden with **Keep sculpt**, and the original shown again. **Pose Reader ▸ Create on Selected Joint** makes a reader that is 1 while the joint's chosen **Axis** points as it does now and falls to 0 at **Cone angle** degrees away (twisting around the axis doesn't count); **Set Cone Angle** changes it later, and **Drive Target** connects it to the target picked in the list. **Targets** lists the loaded mesh's blendShape targets with their weight and what drives them: **Set Weight**, **Rename...**, **Delete** and **Disconnect** (stop a reader driving it). Each is one undo step. Pose reader connections aren't saved by an Assembler BlendShapes item
- Assembler: **folders have versions**. Right-click **Publish** on a folder records the version every item inside it is at, subfolders included, as the folder's next version. It can't be published while an item in it has changes not published yet; the message names them so you can publish them first. Like a file, the folder's Version column shows its version, and a `*` (e.g. `v002*`) once it no longer matches: an item added, deleted or renamed, or one published or switched to another version. Picking a version under **Versions** sets every item in the folder back to the version it recorded, and asks first only if that would lose an item's unpublished changes. Items deleted since are named as not restored; items added since are left as they are. Folder versions are kept in the hidden `.versions` folder next to it, follow it when it's renamed or moved, and are deleted with it
- Assembler: **build plans**. Right-click a folder (or empty space, for the whole tree) ▸ **Build ▸ Export...** saves everything in it as one JSON file (a folder's file holds the folder itself, so importing it brings the whole folder back): its folders and items in build order, which are disabled, each Script's code, each Scene's Maya file path, and each Rig Module's module and parameters. Mesh, Joints, SkinCluster and the other published-data items are saved as empty entries to publish into, and versions and run logs aren't included. **Build ▸ Import...** creates a plan's items in the folder, after what's already there; imported items start with no versions. Import checks the whole plan first (names, item types, rig modules and their parameter values) and, if anything is wrong, lists every problem and creates nothing. An item whose name is already in the folder gets a new one, as Paste does (`setup.py` becomes `setup_copy.py`). Use it to share build templates, or to bring in a build an AI wrote
- **ControlShape Tool**: a library of control shapes with previews: 16 built-in presets (circle, square, triangle, half circle, star, cross, arrow, double arrow, four arrows, cube, sphere, cylinder, diamond, pyramid, pin, locator) plus your own: **Save Selected...** saves the selected control's shapes (without colors) as a preset in your Maya user folder (`kaiju_suite/control_shapes`), and **Delete** removes a saved one. **Create** (or double-click) makes a `<name>_ctrl` with the preset at each selected node's position and orientation, or one at the origin, at the chosen **Size**. **Replace** swaps the selected controls' shapes for the preset, keeping their color and line width, and their size with **Keep size**; a joint or group with no shapes gets its first one. **Edit Shapes** rotates (X / Y / Z by an angle), scales (**Bigger** / **Smaller**) and moves (+X ... -Z by a step) the selected controls' shapes around their pivots without moving the controls. **Mirror to Opposite** gives each selected control's opposite (`L_` / `R_`, ...) its shapes mirrored across X, keeping the opposite's color; **Copy from First** gives the other selected controls the first one's shapes. Color swatches set the shapes' index color (or turn it off), and **Set Line Width** their line width. Each is one undo step
- **DeltaMush Tool**: paint where a deltaMush acts. **Add DeltaMush** adds one on top of the selected meshes' deformers with every weight at 0, so it does nothing until you paint it in (or at 1, to paint it out). **Load Selected** picks the selected mesh and its deltaMush; **Paint** opens Maya's Paint Attributes tool on its weights. **Set Selected** sets the selected vertices (or faces, edges) to a value, **Flood** sets every vertex, **Invert** turns each weight w into 1 - w, **Mirror +X to -X** / **-X to +X** copies one half's weights onto the other, and **Select Affected** selects the vertices it acts on. Each is one undo step
- **SkinCluster Tool**: **Copy Skin** copies the first selected mesh's weights onto the other selected meshes, matching vertices by **Closest Point**, **UV** (current UV sets, wherever the meshes are) or **Topology** (same vertex IDs; needs the same vertex count). A target with no skinCluster is bound to the source's influences; a skinned one gets the influences it's missing. **Mirror Skin** mirrors the selected meshes' weights across X, +X to -X or back, matching joints by position. **Prune Weights** zeroes weights below a threshold, **Remove Unused Influences** removes influences with no weight, and **Select Influences** selects them. Each is one undo step
- **Pose Tool**: **Mirror** poses each selected control's opposite as its mirror image across X; **Flip** swaps the poses of the selected controls and their opposites, mirrored. Opposites are found by name (`L_`/`R_`, `_L`/`_R`, `l_`/`r_`, `left`/`right`, `Left`/`Right`, also camelCase like `leftEye`); a control with no side mirrors onto itself. Translate and rotate are worked out from each control's parent and joint orient, so world-aligned controls and joints mirrored with Behavior or Orientation all come out mirrored in the world (rotate axis isn't taken into account); scale and custom attributes are copied as they are. Locked or connected attributes on the other side are skipped with a warning. **Opposite** / **Add Opposite** select the other side; **Reset to Default** sets every keyable attribute to its default. Each is one undo step
- **Mesh Tool**: checks meshes for problems: n-gons, non-manifold geometry, lamina faces, zero-area faces, zero-length edges, open borders, faces without UVs, locked normals, vertices with no mirror across X, unfrozen transforms, construction history (deformers don't count), duplicate names and shapes not named `<mesh>Shape`. **Check** runs the turned-on checks (remembered) on the selected meshes, or every mesh if nothing is selected, and lists what each found per mesh; **Select** (or double-click) selects the faces, edges, vertices or meshes found. **Fix** repairs unfrozen transforms (like Freeze Transformations), history (keeps deformers), locked normals and shape names, as one undo step, then checks again
- Menu: the **Rig Module Editor** is no longer under **Kaiju ▸ Utilities**. Open it by double-clicking a Rig Module item in the Assembler
- Rig modules: **Simple IK** has a new **Color** parameter, a Maya index color (0 to 31, as in Drawing Overrides) that both its controls get; new items default to 17 (yellow), and 0 leaves Maya's default color. Existing Simple IK items get 17 too. The Rig Module Editor shows it as a drop-down of color swatches
- Rig modules: six new modules, each under **New** in the Assembler and edited in the Rig Module Editor like Simple IK. Every one has a **Color** parameter for its controls (default 17, yellow), checks its parameters before building and changes nothing if any are wrong, doesn't move your joints when it builds (except Spline IK with a curve, below), and is reverted by one undo:
  - **Root**: needs no joints. Builds `<name>_root_grp` at the world origin with a large flat root control and a smaller offset control under it; build the rest of the rig under the offset control. The root control's keyable **globalScale** (default 1) scales it evenly; its own scale channels are locked and hidden. Name defaults to `main`, control size to 10
  - **Single FK**: one joint. Builds `<name>_fk_grp` with a circle control on the joint, matching its orientation; the joint follows the control's translation and rotation
  - **FK Chain**: a start and end joint (at least 2 joints). Builds `<name>_fkChain_grp` with one circle control per joint, `<name>_01_fk_ctrl`, `<name>_02_fk_ctrl`, ..., each nested under the one before, so rotating a control carries everything below it. Turn off **End control** when the end joint is just a tip
  - **Stretchy IK**: like Simple IK (a rotate-plane IK control at the end joint and a pole vector control), in `<name>_stretchIk_grp`, and when the IK control is pulled further than the chain reaches, every bone lengthens by the same amount so the end joint stays on the control. Within reach bones keep their length. The IK control's **stretch** attribute (0 to 1, default 1) turns stretching off or blends it. Joints below the start joint can't have locked or connected translation. Its control names are the same as Simple IK's, so don't give a Simple IK and a Stretchy IK the same name. Deleting the group by hand leaves the stretch nodes driving the joints: undo the build instead
  - **IK/FK**: a start and end joint (at least 3, with a bend). Copies the joints into an IK chain and an FK chain inside `<name>_ikfk_grp`. The IK side works like Simple IK; the FK side has one nested circle control per joint. A switch control beside the end joint has an **ikFk** attribute: 0 is FK (the default), 1 is IK, values between blend. Your joints aren't reparented; they follow the blend. IK controls show only while ikFk is above 0, FK controls only while it's below 1
  - **Spline IK**: a start and end joint (at least 3) and an optional NURBS **Curve**.
